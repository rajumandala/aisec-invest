## How the notes are built

Every note follows the same pattern:

1. **It starts from the previous problem.** The opening line restates the problem the last note ended on.
2. **It adds one idea to the same assistant.** The code changes as little as possible from the previous note.
3. **It shows the security point with a real run.** That means a real request or a real attack, not only theory.
4. **It names the OWASP risks.** A short table lists each OWASP risk the note meets, the issue it causes in the assistant, and the fix.
5. **It ends on the next problem.** The last section names what the assistant still cannot do safely, and links to the note that solves it.
