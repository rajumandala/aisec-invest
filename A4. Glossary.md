Every term used in Part 1, in plain words. The number after each entry is the note that teaches it. Terms used only in the Part 2 deep dives are explained in those notes.

The course assumes no background in AI, security or the stock market. If a word in a note is not here and not explained where it appears, that is a gap in the notes.

## AI and security terms

| Term | Meaning | Note |
|---|---|---|
| **A2A (Agent2Agent)** | An open protocol that lets one company's AI agent send tasks to another company's agent | 13 |
| **Agent** | A model that runs in a loop: it asks for tools, reads their results and decides the next step until the job is done | 4 |
| **Agent Card** | A small file an A2A agent publishes, saying what it does and how to reach it. It is the owner's claim, not proof | 13 |
| **Agent framework** | A library that provides the agent loop, tools and handoffs, so a team does not write them by hand | 11 |
| **Allowlist** | A list of the only things allowed, such as reviewed sites or tools. Anything not on it is refused | 6, 9a |
| **Ambient authority** | Powers an agent holds just because of where it runs, such as the logins in a person's browser, whether or not the task needs them | 9a |
| **API, API key** | An API is the set of requests a service accepts from other programs. An API key is the secret that proves who is calling, and who pays | 1 |
| **Attack surface** | Everything an attacker can reach and send input to | 10 |
| **Audit log** | A record of every request, tool call and order, kept as evidence and protected from editing | 15 |
| **Build pipeline, gate** | The automated steps every code change passes through before it goes live. A gate is a step that can stop the change | 5 |
| **Classifier** | A small model trained to sort text into categories, such as "injection" or "not injection". It gives a probability, not a certainty | 10a |
| **Confused deputy** | A program with wide powers, tricked into using them for someone who has fewer | 7a, 9a, 12 |
| **Container, microVM** | Two kinds of sandbox wall. A container is a walled-off process that shares the machine's operating system. A microVM is a tiny virtual machine with its own, which is stronger | 9 |
| **Context** | Everything the model reads in one call: instructions, messages, tool results | 1, 8a |
| **Context engineering** | Deciding on every call what the model gets to read, and rebuilding it from data in code | 8a |
| **Dependency** | Outside code that an app is built from. A malicious update to it is a supply-chain attack | 6 |
| **Embedding, vector** | A list of numbers that stands for the meaning of a text. Texts with similar meanings get similar lists | 7 |
| **Eval (evaluation)** | A test case for an AI app: who is logged in, what they type, and what should happen. Run several times, because outputs vary | 5 |
| **Fail closed, fail open** | When a check cannot run, failing closed means refusing the action; failing open means letting it through. Security checks fail closed | 6, 14 |
| **False positive** | Harmless input that a check wrongly flags as an attack | 10a |
| **Guardrail** | A check on text going into or coming out of the model | 10a |
| **Handoff** | One agent passing work, and often text, to another | 9 |
| **Hard and soft controls** | A hard control is code the model cannot talk its way past. A soft control asks a model to behave | 7, 14 |
| **Hash, fingerprint** | A short code computed from some text, which changes completely if one character changes. Used to notice that something changed | 6 |
| **IDOR** | Insecure direct object reference: an app lets the caller name any record, such as an account, and never checks that it is theirs | 3 |
| **Instruction hierarchy** | Training that makes a model rank the developer's instructions above the user's, and tool results below both. A habit, not a boundary | 10 |
| **Jailbreak** | Text that gets a model to say what its provider trained it to refuse. Different from prompt injection, which attacks the app | 10 |
| **Kill switch** | One setting that turns the assistant off while the rest of the app keeps working | 14 |
| **Lethal trifecta** | An agent with private data, untrusted input and a way to send data out. With all three, an injection can steal data | 10b |
| **LLM, model** | Large language model: a program trained on a huge amount of text that writes the most likely next text. It can follow instructions and fill in forms | 1 |
| **Markdown** | A way of writing text that apps turn into links, images and formatting. A rendered image fetches its address without a click | 6, 10a |
| **MCP (Model Context Protocol)** | A standard way for a company to publish tools that any AI app can list and call | 6 |
| **Memory** | Facts our code saves about a user and puts back into the context in later sessions | 8 |
| **Multimodal** | A model that reads images, PDFs or audio as well as text | 9a |
| **OAuth** | The standard behind "Sign in with Google": a user grants an app a limited token instead of their password | 12 |
| **OWASP** | An open security community. Its Top 10 lists name the most important risks, with codes such as LLM01 and ASI01 | 1, A1–A3 |
| **Pentest (penetration test)** | Testers breaking into a system, with permission, to find the holes before attackers do | 10 |
| **PII** | Personally identifiable information: data that identifies a person, such as a PAN | 10a |
| **Pin** | Record the exact version, or fingerprint, of something you reviewed, and refuse anything different | 6 |
| **Principal** | A user or group that a permission is granted to. (In note 15, the legal sense: the party answerable for orders) | 7a |
| **Prompt** | The text sent to a model | 1 |
| **Prompt injection** | Text written to make a model follow the writer's instructions instead of the app's. **Direct** if the user types it; **indirect** if it hides in content the model reads | 3, 7, 10 |
| **RAG (retrieval-augmented generation)** | Search first, then answer: code finds relevant documents and gives them to the model | 7 |
| **Red teaming** | Attacking your own system the way a real attacker would, before they do | 10 |
| **Retrieval poisoning** | Writing content so it ranks first in the assistant's search and shapes the answer, without any instruction in it | 7 |
| **Rug pull** | A vendor changing its tools after you reviewed them, under the same names | 6 |
| **Sandbox** | A walled-off place to run code you do not trust, with no secrets, no network and limits on everything | 9 |
| **Schema, structured output** | A fixed shape the model's answer must match, such as an order with a stock, a side and a quantity | 1 |
| **Scope** | One named power inside a token, such as "read holdings". A token carries only the scopes granted | 12 |
| **SDK** | A code library a company publishes so others can use its service | 6 |
| **Separation of duties** | Splitting powers so no single part can do something dangerous alone, such as reading attacker text and placing orders | 9 |
| **Session** | The record that a user is logged in. Identity comes from it, never from what a model writes | 3 |
| **SQL injection** | The classic attack where a user's text ends up inside a database query and changes what it does | 9 |
| **Stored XSS** | Cross-site scripting: an attacker saves a script in a web page, and it runs in every visitor's browser with their rights | 7 |
| **Supply-chain attack** | Attacking something you rely on, such as a vendor or a library, instead of attacking you | 6 |
| **Taint tracking** | Labelling each value with where it came from, so code can refuse to let untrusted values reach a power | 10b |
| **Threat model** | A map of a system's parts, the data that flows between them, and how each could be attacked | 10, 14 |
| **Token (two meanings)** | 1. A small piece of text, about three-quarters of a word, that models read and charge by. 2. A signed digital pass that says who may do what, until when | 1, 12 |
| **Tool calling** | The model asking our code to run a named function and send back the result. The model never runs anything itself | 3 |
| **Tool poisoning, tool shadowing** | Instructions hidden in a tool's description. Shadowing is one server's description steering another server's tools | 6 |
| **Tracing** | A record of every step of every run: which model call, which tool, what came back | 11 |
| **Trust boundary** | A line in the system where data goes from something you control to something you do not, or back | 14 |
| **Unicode, ASCII smuggling** | Unicode gives every character in every script a number. Some of its characters are invisible, and can hide instructions that models still read | 10 |
| **Vector database** | A database built to store embeddings and find the closest ones to a question | 7a |
| **WAF** | Web application firewall: a filter in front of a website that blocks requests it recognises as attacks | 10a |

## Market and broker terms

| Term | Meaning | Note |
|---|---|---|
| **Algorithmic trading, algo ID** | Orders generated by software. In India, algorithms above a set speed must be registered and their orders tagged with an ID | 15 |
| **Average buy price** | What the investor paid per share, on average, for a stock they hold | 4 |
| **Book profit, gainer** | A gainer is a stock now worth more than the investor paid. To book profit is to sell it and take the gain | 4 |
| **Contract note** | The document a broker sends after each trading day, listing the client's trades and charges | 7a |
| **Delivery, intraday** | Delivery means buying shares to keep. Intraday means buying and selling within the same day | 8 |
| **Demat account** | The electronic account that holds an investor's shares | README |
| **DDPI** | Demat Debit and Pledge Instruction: an investor lets the broker do one limited thing with their demat account, not everything | README |
| **Exchange, NSE** | The market where orders are matched. The NSE is the National Stock Exchange of India | 2 |
| **F&O** | Futures and options: high-risk contracts that most investors cannot trade until they ask for it | 6, 8 |
| **Fat-finger order** | An order typed wrong by accident, such as an extra zero | 2 |
| **GTT** | Good-till-triggered: an order that waits until a set price is reached | 6 |
| **Holdings** | The shares an investor owns | 3 |
| **Instrument master** | The broker's list of everything that can be traded, with its symbol | 2 |
| **Investment adviser** | A person or firm registered with SEBI to give investment advice for a fee | 15 |
| **KYC** | Know Your Customer: the identity checks a broker must do on every client | 9a |
| **Lakh** | One hundred thousand. ₹5 lakh is ₹500,000 | 2 |
| **Limit order, market order** | A limit order executes only at the stated price or better. A market order executes at whatever the price is | 1 |
| **LTP** | Last traded price: the price of the most recent trade in a stock | 6 |
| **PAN** | Permanent Account Number: an Indian tax ID, and personal data | 9a |
| **Penny stock** | A very cheap share that trades little and is easy to manipulate | 8 |
| **Price band** | A check that rejects an order whose price is too far from the live price | 3 |
| **Pump-and-dump** | Pushing a stock's price up with hype, then selling to the buyers it attracted | 7 |
| **RMS** | Risk management system: the broker's software that checks every order against its limits before it reaches the exchange | 2 |
| **SEBI** | Securities and Exchange Board of India, the market regulator | 13, 15 |
| **Settlement** | When the exchange actually moves the shares and the money, usually the next working day | 4 |
| **Small-cap** | A company whose shares are worth little in total. Its price is easier to move | 10 |
| **Zerodha, Kite** | A large Indian broker, and its trading app | 6 |
